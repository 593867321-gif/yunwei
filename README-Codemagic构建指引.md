## 三、准备 Apple 签名材料（关键）

IPA 要能装到真机必须签名。本包采用**引用名方式**：先把证书和描述文件上传到 Codemagic，yaml 按名字引用它们。

### 🔴 为什么不能用「自动签名」（实测踩坑记录）

`codemagic.yaml` 里**绝不能**配置 `ios_signing.distribution_type + bundle_identifier`，两个原因都是实测踩到的：

1. 配了之后 Codemagic 在**构建启动时**就强制拉取签名材料，拉不到立刻中止，后面的脚本步骤（含自动创建）根本没机会执行。报：
   `No matching profiles found for bundle identifier "com.youdake.operation.ios" and distribution type "ad_hoc"`
2. 更致命的是：账号里唯一的分发证书是 **`Distribution Managed`**（Xcode Cloud 云端托管证书），**私钥由 Apple 保管，任何人都下载不到**。Codemagic 拉到它后无法保存，报：
   `Cannot save Signing Certificates without certificate private key`

   官方文档对此有明确表述：*"Fetching a certificate that was not generated by Codemagic is not possible because each certificate is linked with a private signing key to which Codemagic has no access."*

**结论：必须让 Codemagic 自己生成一张它持有私钥的证书。** 下面两步做完即可，配额充足（普通分发证书当前 0 张，上限 2 张；那张托管证书不占这个额度）。

### 步骤 1：生成 Apple Distribution 证书

Codemagic → **Team settings** → **Code signing identities** → **iOS certificates** 标签：

1. 点 **Generate certificate**
2. **Reference name** 填 `youdake_dist`（必须一字不差，yaml 按此名引用）
3. **Certificate type** 选 **Apple Distribution**
4. **App Store Connect API key** 选 `youdake-asc`
5. 点 **Create certificate**

> 🔴🔴 **创建完成后页面会给出 .p12 下载链接和一串密码——必须立刻点下载并把文件存好。**
> 官方明确：**这个 .p12 只能下载一次**，关掉页面就永久拿不到，只能重新生成。
> （上一轮就是只记了密码、没下载文件，导致证书列表为空 "No certificates shared with the team"，白跑一次构建。）

6. **先看列表**：生成后若 iOS certificates 列表里**已经出现** `youdake_dist`，说明已自动登记，**跳过上传**，直接做步骤 2。
   若列表仍为空（显示 "No certificates shared with the team"），则需在**同页的 Upload certificate 区**上传刚下载的 .p12：
   - **Certificate password**：填 Codemagic 给你的那串密码（**只填在这个框，不要写进任何文件、不要发给任何人**）
   - **Reference name**：`youdake_dist`（与生成时填的保持一致）
   - 点 **Add certificate**

无论走哪条，最终列表里都应有 `youdake_dist`，类型为 Apple Distribution。**确认它存在再往下做**，否则构建必然失败。

### 步骤 2：创建并上传 Ad Hoc 描述文件

账号里目前没有 Ad Hoc 描述文件（这正是第一次构建报错的原因），需手动建一个：

1. 打开 https://developer.apple.com/account/resources/profiles/list → 点 **+**
2. 在 **Distribution** 下选 **Ad Hoc** → Continue
3. **App ID** 选 `com.youdake.operation.ios` → Continue
4. **Certificates** 勾选刚生成的那张 **Apple Distribution**（注意：不要选 `Distribution Managed`，那张没私钥用不了）→ Continue
5. **Devices** 全选（已登记 6 台：Super.iPhone15Pro、超级.iPhoneX、内部1、庄、焦、黄碧玉）→ Continue
6. Profile Name 随意（如 `youdake operation adhoc`）→ **Generate** → **Download**
7. 回 Codemagic → **Code signing identities** → **iOS provisioning profiles** 标签 → 上传下载的 `.mobileprovision`
   - **Reference name** 填 `youdake_adhoc`（必须一字不差）
   - 点 **Add profile**

上传后该页会显示 bundle id 与到期日，且 **Certificate 字段应有绿色对勾**（表示匹配到 `youdake_dist`）。没有对勾说明证书没传好或引用名不对，构建仍会失败。

### 🔴 ad-hoc 包的安装限制

ad-hoc 包**只能装到描述文件里包含的设备**。上述 6 台都已登记，可直接安装（蒲公英扫码或 Apple Configurator 均可）。

以后新增测试机：登记 UDID → 在 Profiles 里 **Edit** 该 profile 勾选新设备 → 重新下载上传到 Codemagic → **重新构建**。已产出的旧 IPA 不会自动获得新设备。

若想不限设备公开测试，改用 TestFlight：把签名换成 App Store 类型描述文件，并在 App Store Connect 把测试人员加为内部测试员。

## 四、配置环境变量（填后端地址与推送密钥）✅ 已完成

> 本节已在控制台配好（已核实 4 个变量均存在），保留说明供日后核对或重建团队时参考。

采用 **App 级加密变量**（不再用分组）。App 级变量会自动注入所有 workflow，比建组少一层概念、不易错。

1. Codemagic → 你的 App → **Environment variables**
2. 逐个添加 4 个变量（左边框填**变量名**，不是组名），每个都**勾选 Secret**，值从你本机 `yunying\env_release.json` 抄：

   | 变量名 | 值 |
   |---|---|
   | `ENV` | `release` |
   | `API_HOST` | `https://youdake.com/team/` |
   | `PUSH_APP_KEY` | （env_release.json 里的值） |
   | `PUSH_APP_SECRET` | 🔴（env_release.json 里的值，机密，别发给任何人） |

3. 这 4 个变量名与代码里 `String.fromEnvironment(...)` 读取的键**完全一致**（已核对：`Const.dart` 读 `ENV`/`API_HOST`，`push_service.dart` 读 `PUSH_APP_KEY`/`PUSH_APP_SECRET`），构建时经 `--dart-define` 注入。

> 🔴 安全红线：`PUSH_APP_SECRET` 等机密值**只填在 Codemagic 网页框里**，不要写进 `.env.ci.template` 或任何文件、不要发出来。`.env.ci.template` 仅供对照变量名。

## 五、触发构建

1. Codemagic → 你的 App → **Start your first build** 或 **Start new build**
2. 选 branch `main`、workflow **「优达客运营 iOS 正式版」**（即 codemagic.yaml 里的 `ios-release`）
   > 🔴 务必选这个，**不要选 Default Workflow**。之前用 Default Workflow 只产出未签名的 `Runner.app.zip`，没有 `.ipa`。
3. 点 **Start build**
4. 等 10-20 分钟。构建日志里密钥会被自动打码（显示为 `***`）


构建会依次执行：装 Flutter 3.41.4 → 设置签名 → `pub get`（用 local_deps 替代库）→ `build_runner` → `gen-l10n` → `pod install` → `flutter build ipa`。

## 七、常见错误排查

| 现象 | 原因 | 解决 |
|---|---|---|
| `pub get` 失败、找不到 itwo_flutter_base | local_deps 没推上去，或 pubspec 仍指向 codeup | 确认 `git status` 里 `local_deps/` 已提交；确认 pubspec 是 `path:` 不是 `git:` |
| `No matching profiles found ... distribution type ad_hoc` | yaml 配了 `ios_signing.distribution_type`，构建启动即强制拉取签名材料而失败 | 删除 `distribution_type`/`bundle_identifier`，改用引用名方式（第三节） |
| `Cannot save Signing Certificates without certificate private key` | 账号里的 `Distribution Managed` 是云端托管证书，私钥由 Apple 保管、下载不到 | 用 Generate certificate 新建一张 Codemagic 持有私钥的 Apple Distribution（第三节步骤 1） |
| `No certificates shared with the team` / 找不到 `youdake_dist` | 证书没上传成功，或生成 .p12 时没及时下载（该文件只能下一次） | 重新 Generate certificate 并**当场下载 .p12**，再上传；确认列表出现 `youdake_dist` |
| profile 上传后 Certificate 字段无绿色对勾 | 描述文件绑的证书与 `youdake_dist` 不匹配 | 重建 profile 时勾选新生成的 Apple Distribution（勿选 Distribution Managed） |
| `requires a provisioning profile with the Push Notifications feature` | profile 没开推送能力 | 描述文件的 App ID 需勾选 Push Notifications（本项目 entitlements 含 aps-environment） |
| IPA 装上但打不开/闪退 | ad-hoc 包未登记该设备 UDID | 把设备 UDID 加进 Apple Developer Devices，Edit profile 勾选后重新下载上传，再构建 |
| 装上能开但连不上后端 | 环境变量没注入或域名错 | 确认 App 级 4 个变量（ENV/API_HOST/PUSH_APP_KEY/PUSH_APP_SECRET）都填了；确认 API_HOST 是你要的 .com |
| 推送收不到 | PUSH_APP_KEY/SECRET 没注入 | 同上，确认这两个变量值正确且勾了 Secret |
| `pod install` 失败 | CocoaPods 源问题 | codemagic.yaml 已用 `--repo-update`；若仍失败可加国内 pod 源 |

## 八、风险提示（同 APK 指引，务必知悉）

1. **替代库非官方原库**。`local_deps/` 里的 `itwo_flutter_base`/`itwo_flutter_net` 是我依据项目 195 处调用反推实现的，已过 50 项行为测试（42 项基础 + 8 项扫码弹窗回归）+ Android 真机验证（你反馈可用），但无法保证与原库 100% 一致。iOS 首次构建后，请重点验证：登录（MD5+BCrypt）、token 持久化（退出重进不掉登录）、**扫码成功弹「二维码秘钥」弹窗**、推送、首页看板与库存刷新。
2. **拿到原库权限后应换回官方依赖重建**：把 `pubspec.yaml` 的两个 `path:` 改回 `git:`，删掉 `local_deps/`，重跑构建。
3. **前后端必须同步发版**：看板接口 `todayRevenue` 由 String 改为数值型，是破坏性变更。后端没部署本次改动的话，首页金额会显示异常。
4. **Flutter 版本**：codemagic.yaml 锁 3.41.4（项目要求）；本机验证用的是 3.47.3。若 CI 上 3.41.4 有兼容问题，可改成 3.47.3（与本机验证环境一致）。
